# Demo Mode

## Purpose
Mode démo sur une **base démo Turso partagée**, distincte de la prod et recopiée chaque nuit depuis la prod, ou à la demande par un SUPER_ADMIN. En démo, les requêtes API lisent et écrivent dans cette base : les actions s'appliquent vraiment (réserver, valider…), sans jamais toucher la prod. Tous les utilisateurs en démo voient les modifications des autres jusqu'à la recopie suivante.

## Key Files
| File | Description |
|------|-------------|
| `readOnly.ts` | Source unique, pure (partagée client/serveur/proxy) : cookie, en-tête `x-crf-demo`, clé localStorage, événement, `DEMO_EXTERNAL_WRITE_ROUTES`, `isDemoExternalWrite`, `isDemoEligibleApi`, `isDemoDbConfigured` (faux si l'URL démo = la prod), `isDemoDbSameAsProd`, `isDemoBlockedRequest(path, method, demoDbConfigured)`, `isQrPage` |
| `server.ts` | Serveur uniquement : `isDemoRequest()` (en-tête `x-crf-demo: 1` posé par le proxy ET base démo configurée ; hors requête → faux), `getDemoClient()` (`null` si non configurée ou égale à la prod) |
| `cloneDatabase.ts` | `cloneDatabase(source, target)` : recopie schéma, lignes (pages, `INSERT OR REPLACE`, parents d'abord), index, vues, déclencheurs, puis index FTS du référentiel reconstruit. Source : `SELECT` seuls. `DemoMeta` (`refreshing` → `ready` + `refreshedAt`, lu par `readDemoState`). `DEMO_SCHEMA_ONLY_TABLES` (`BrandCredential`, `RenaultSession`, `McpToken`, `PushSubscription`) et leurs dépendantes par clé étrangère (`VehicleConnection`) : schéma sans lignes |
| `refresh.ts` | `refreshDemoDatabase()` : la recopie partagée par le cron et `POST /api/demo/refresh`. Verrou `DemoRefreshLock` à bail de 6 min, puis `cloneDatabase` et purge R2. Ne lève jamais ; résultat typé `not-configured \| locked \| failed \| ok` |
| `fetchInterceptor.ts` | Enveloppe `window.fetch` : simule les seules écritures de `DEMO_EXTERNAL_WRITE_ROUTES` (hors pages QR), émet `crf-demo-simulated` |

## Mise en place (une fois)
1. `turso db create crf-demo` puis `turso db tokens create crf-demo`.
2. Variables Vercel (prod et preview) : `TURSO_DEMO_DATABASE_URL`, `TURSO_DEMO_AUTH_TOKEN`.
3. La base se remplit à la recopie suivante (fin du cron `/api/cron/daily-mileage-check`, 23h59, ou bouton « Recopier la base démo » de la page Aide pour un SUPER_ADMIN). Sans ces variables, `GET /api/demo/status` répond `{ available: false }` et le bouton d'activation est masqué.

## For AI Agents
- **Aiguillage dans `src/lib/db.ts` uniquement** : `db` résout le client à chaque appel (`headers()` de `next/headers`). Le cookie est partagé entre onglets ; l'en-tête `x-crf-demo: 1`, lui, n'est posé par `src/proxy.ts` que sur une API hors QR (`/api/qr*`) et hors `/api/auth/`, et toute valeur envoyée par le client est retirée. Le cookie reste posé sur les pages QR (aligné sur la démo choisie, pas sur la page). Jamais de choix de base route par route. `prodDb` = toujours la prod (auth, crons, recopie) ; `demoDb` = base démo ou `null`.
- `src/auth.ts` (utilisateur, rôles, UL de session) lit toujours `prodDb`. Un compte créé en prod après la dernière recopie n'a ses données démo qu'après la recopie suivante.
- Effets externes neutralisés en démo, côté lib : pas de Web Push (`push.ts`, la notification in-app reste en base démo), R2 transparent sous le préfixe `demo/` (`putObject` écrit `demo/<clé>`, les lectures — `getObject`, `headObject`, `getObjectSize`, `getObjectRange`, `presignUrl` GET/HEAD — lisent `demo/<clé>` puis la vraie clé, `deleteObject` ne supprime que `demo/<clé>`, `presignUrl('PUT')` refusé ; `purgeDemoObjects()` vide `demo/` chaque nuit après la recopie) — la base démo référence les fichiers de la prod. Aucun appel Renault : `authenticateBrand` lève `BrandTransientError('… indisponible en mode démo')`, sans changement de statut.
- **Toute nouvelle route qui écrit hors base (R2, API externe) doit rejoindre `DEMO_EXTERNAL_WRITE_ROUTES`** : elle est alors simulée côté client et refusée (403) par `src/proxy.ts`.
- Garde-fou : base démo non configurée + cookie de démo → `src/proxy.ts` refuse toute écriture `/api/` non exemptée (403 `{ error: 'Mode démo : lecture seule', demo: true }`). Le proxy tourne sous Node (Next 16) et lit `process.env.TURSO_DEMO_DATABASE_URL` à chaque requête.
- Recopie : `refreshDemoDatabase()` (`refresh.ts`) en fin de `/api/cron/daily-mileage-check`, après le contrôle kilométrique ; tout échec est journalisé (`[demo] …`) et la réponse du cron ne change pas. Refusée si l'URL démo désigne la prod. Non atomique : un échec laisse `DemoMeta.state = 'refreshing'`, et `GET /api/demo/status` répond `available: false, refreshing: true` jusqu'à la recopie réussie suivante. `DemoMeta` passe à `refreshing` avant même la lecture du schéma source : une source illisible laisse aussi la démo indisponible.
- Pas de bascule pendant `refreshing` : `DemoContext` ne quitte pas la démo d'une personne qui y est déjà (erreurs visibles, sortie manuelle possible), seulement quand `available` est faux sans `refreshing`. Pas de blocage serveur : les écritures parasites restent possibles, uniquement dans la démo. `isDemoRefreshing` retire le bouton d'entrée de la page Aide ; `markDemoRefreshing()` l'active dès le clic sur le bouton de recopie, et la relecture du statut remet l'état à jour.
- Recopie manuelle : `POST /api/demo/refresh` (`isSuperAdmin` vérifié côté serveur, sous `withAudit`, `maxDuration = 300`) lance le même code : 200 `{ success, tables, rows, durationMs, purged }` (`purged: null` si seule la purge R2 échoue), 503 base non configurée ou égale à la prod, 409 recopie en cours ou tout juste interrompue, 500 générique (détail dans les logs). Bouton `src/components/demo/DemoRefreshButton.tsx` sur la page Aide, affiché selon `canRefreshDemo` (`canRefresh: true` de `GET /api/demo/status`, jamais renvoyé aux autres comptes), masqué en démo. La purge R2 impose la présence de la route dans `DEMO_EXTERNAL_WRITE_ROUTES` : le proxy la refuse (403) en démo. Route exclue du MCP (`EXCLUDED_API_PREFIXES`, `src/lib/mcp/routes.ts`) : un jeton en écriture effacerait la démo partagée sans confirmation, et l'appel serait abandonné à 50 s alors que la copie continue.
- Verrou : table `DemoRefreshLock` **dans la base démo** (la prod ne reçoit que des `SELECT`), créée à la volée, sans migration ; `readSchema` de `cloneDatabase.ts` l'exclut, sinon la recopie la supprimerait. Prise atomique par `INSERT … ON CONFLICT … WHERE startedAt < ?` (`rowsAffected = 0` : verrou tenu), libérée en `finally`. Bail de 6 min, supérieur au `maxDuration` de 5 min : un verrou expiré vient d'une fonction tuée et la recopie suivante le reprend. Ne pas utiliser `DemoMeta` : `refreshing` persiste après un échec et ne dit pas depuis quand.
- Statut conservé dans `localStorage` (`crf_is_demo_mode`) **et** dans le cookie `crf_demo_mode=1` (`path=/`, `SameSite=Lax`), synchronisés par `DemoContext`, qui expose aussi `isDemoAvailable` et `canRefreshDemo` (`GET /api/demo/status`), `refreshDemoStatus()` pour relire ce statut, et quitte une démo devenue indisponible.
- Pages QR (`/qr`, `/qr-ul`, `/qr-stock`, `/qr-uniforms`) : démo désactivée (prod, pas de bandeau).
- Un formulaire qui lit un champ de la réponse d'une route externe simulée doit tolérer `simulated: true` (pas d'`id`, pas de `token`).
