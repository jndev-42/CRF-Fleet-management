En-tête
①
pdfkit
Logo + nom app en blanc sur fond var(--crf-red). pdfkit : doc.rect().fill().text()
②
Titre du rapport + période exportée (passée en paramètre depuis le POST body).
③
Date/heure de génération côté serveur : new Date().toLocaleString('fr-FR')
Contenu
④
SQL
KPIs : résultat des 4 agrégats SQL globaux. Encadrés avec bordure rouge en haut.
⑤
Tableau chauffeurs : ORDER BY tripCount DESC. Colonne "vs. moyenne" calculée server-side avant génération.
⑥
Tableau véhicules avec mini barres pdfkit : doc.rect(x, y, width * pct, 3).fill(color)
Pagination
⑦
Footer paginé : doc.on('pageAdded', () => drawFooter()). Numérotation automatique.
Graphiques
⑧
pdfkit
Option A : Pas de graphiques dans le PDF (données tabulaires suffisantes, plus fiable).

Option B : Générer un PNG des charts côté client (canvas.toDataURL), l'envoyer dans le POST body, le pdfkit l'intègre via doc.image(buffer).
⑨
Répartition missions : tableau avec barres inline dessinées en pdfkit (rect fill).
⑩
Section incidents : texte descriptif en rouge #DC2626. Affiché uniquement si incidents > 0.
Architecture
POST /api/stats/pdf
1. Reçoit { dateFrom, dateTo }
2. Exécute les SQL agrégats
3. Génère le PDF avec pdfkit
4. Stocke en mémoire : global.__pdfJobs.set(jobId, buffer)
5. Retourne { jobId }

GET /api/stats/pdf?jobId=xxx
→ Retourne le Buffer PDF avec
Content-Type: application/pdf
Content-Disposition: attachment
